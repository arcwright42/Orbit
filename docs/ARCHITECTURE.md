# Orbit 架构与开发进度

更新日期：2026-10-11。

Orbit 使用 TypeScript、Electron、React 和 Vite。当前提供桌面需求收集、附件、任务看板、Qwen 实时语音与本地唤醒。团队连接与执行代码已移除，执行方案另行确定。产品需求中的完整团队工作流程仍是后续目标。

## 模块职责

| 目录 | 职责 | 边界 |
| --- | --- | --- |
| `src/renderer` | 页面、用户输入、语音采集播放与可见状态 | 通过预加载接口访问应用能力 |
| `src/desktop` | 窗口、菜单、文件选择、麦克风权限与受限 IPC | 调用应用和领域用例 |
| `src/application` | 协调需求收集、附件与持久化 | 供应商协议留在对应领域 |
| `src/domains/conversation` | 需求保存后的系统回执 | 回执明确需求尚未派发 |
| `src/domains/tasks` | 需求任务、校验、去重、待派发取消 | 当前支持本地需求管理 |
| `src/domains/voice` | Qwen WebSocket 会话、本地关键词检测 | 模型只能调用查询任务和保存需求工具 |
| `src/domains/materials` | 附件副本和元信息 | 文件内容解析尚未接入 |
| `src/infrastructure` | SQLite 初始化与事务 | 状态规则由领域负责 |
| `src/contracts.ts` | 可序列化的客户端应用接口 | 逐项暴露必要能力 |

数据库访问放在领域仓储和基础设施中。同一数据库允许跨领域事务，以原子方式保存需求与系统回执。后续按实际复杂度拆分应用服务。

## 当前数据与状态

- SQLite 保存需求任务、系统回执和附件元信息。文件内容独立保存，数据库记录平台管理的路径。
- 提交以请求标识去重。同一个标识提交不同内容会被拒绝。
- 任务和消息在同一事务提交；附件不存在时整个提交回滚。
- 当前新建任务只有“待派发”和“已取消”两个真实状态。看板中的其他列为后续执行能力预留。
- 文本输入直接保存为需求。语音模型能够聊天、查询任务，并在用户明确要求时保存需求。
- 语音转写仅保留在当前界面会话；保存的需求进入 SQLite。
- 新数据库仅创建当前使用的业务表。已有数据库中的旧设置、对话与执行记录不删除，当前代码不读取其废弃功能。移除代码不代表已完成历史执行任务的迁移或恢复。

## 桌面与语音边界

Electron 渲染进程使用 context isolation 和 sandbox，禁用 Node integration。预加载只暴露逐项应用接口；主进程校验调用来源。文件通过系统选择器导入，再按附件标识打开副本。

语音配置从本地 `.env` 读取，密钥只在主进程使用。Qwen 仅负责语音交互，通过 `list_tasks` 和 `save_request` 调用应用能力；当前没有团队创建、任务执行和持续文本模型入口。

语音支持流式播放、服务端 VAD 打断和结束后释放麦克风。启用唤醒时先在本机检测“Hey Orbit”，命中后连接云端。关闭窗口保留应用，退出应用停止语音并关闭数据库。真人唤醒率、扬声器回声和弱网表现仍需实测。

## 后续开发边界

1. 确定持续文本交互与历史保存的恢复方案。
2. 确定最小执行场景和运行时接入方式，再实现派发、状态、取消与恢复。
3. 接入需要用户决定的问题、成果与验收，验证后台任务与主入口的职责隔离。
4. 按场景增加附件内容处理，复用 Relay 中适用的产品流程。

上述是开发方向，具体实现与验收范围需在对应阶段确定。

## 验证方式

`npm run check` 执行类型检查、离线测试和构建。测试覆盖需求去重、事务回滚、取消、附件副本与重启持久化，以及语音会话就绪、工具回执和停止隔离。

`npm run test:desktop` 使用独立临时数据目录，覆盖需求保存、任务看板、取消、重启恢复和语音设置入口，截图输出到 `artifacts/`。GitHub CI 执行干净依赖安装、类型检查、离线测试和构建。

`node scripts/voice-smoke.mjs` 为显式联网验证，使用模拟麦克风检查官方 Qwen 会话、停止和本地唤醒初始化；它不证明真人语音或回声处理质量。
